# OceanBase Connector/J V2.4.13

## 版本信息

* 发布时间：2024 年 10 月 21 日
* 版本号：V2.4.13

## 版本定位

JDBC V2.4.13 版本 Oracle 模式可采用 `array binding` 支持 `RETURNING ... INTO ...` 语句的方式来实现 `Statement.getGeneratedKeys` 方法，以获取批量操作的结果集。同时，去除了用户自定义类型在驱动中存在的缓存影响，解决了一系列严重缺陷，例如在文本协议和二合一协议下，`getMetaData` 返回 `null` 的问题，显著提升了 JDBC 的稳定性。

## 新增特性

* V2.2.11 版本，新增 ArrayBinding，V2.4.13 版本 Oracle 模式下可采用 `array binding` 支持 `RETURNING ... INTO ...` 语句的方式来实现 `Statement.getGeneratedKeys`，以获取批量操作的结果集。需要设置参数为 `compatibleOjdbcVersion=8&useArrayBinding=true&useOraclePrepareExecute=true`。

## 缺陷修复

本次迭代修复的主要问题如下：

* 修复了当 `useServerPrepStmts` 为 `false` 时，`prepareStatement` 之后调用 `getMetaData` 返回 `null` 的问题。
* 修复了使用 `ps.addBatch()` 和 `RETURNING INTO` 时，报错 “not support batch operation for DML_Returning_Into feature” 的问题。
* 修复了在使用 `executeBatch` 时，当 `maxBatchTotalParamsNum` 的值小于实际执行的参数数量且 `useServerPrepStmts` 为 `true` 时存在的语句重复执行问题。
* 修复了使用无效列索引获取返回结果时导致的阻塞问题。
* 修复了将 UDT 类型从集合类型更改为对象类型时可能发生的 `NumberFormatException` 错误。
* 修复了在 JDBC 与复杂类型（UDT 类型构成的数组）作为过程返回参数时，UDT 定义发生变化时出现的错误。
* 修复了更改 UDT 类型定义并嵌套数组时，在执行过程中出现数组越界的问题。
* 修复了将 UDT 类型更改为数组后，执行后 `getArray` 返回类型为 `TYPE_OBJECT` 的错误问题。
* 修复了在 MySQL 模式下，当表名带有反引号 \` 时，`DatabaseMetadata` 下 `getColumns` 接口无法获取注释内容的问题。
* 修复了 PL 语句注释包含 `//`，后续有字段 `{xxx}` 时导致的报错问题。
* 修复了在过程/函数下调用 `getParameterCount` 接口与原生 ORACLE JDBC 不一致的问题。
* 修复了存储过程注册时出参参数未报错的问题。
* 修复了 Oracle 模式下，`getFunctionColumns` 返回结果集不正确的问题。
* 修复了导出时间类型数据的精度问题。
* 修复了 Oracle 模式下，PS 协议 PL 语句 cursor 超限处理的问题。
* 修复了 ODC 获取非法日期时与 MySQL 原生连接器不一致的问题。
* 修复了触发 `SocketTimeOut` 异常后未及时释放 socket 的问题。
